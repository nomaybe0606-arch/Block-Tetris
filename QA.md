## Не подтверждено живым браузером

Автоматизация Chrome через Computer Use была остановлена самим инструментом: он не смог уверенно определить текущий URL Windows-браузера для применения своей политики. После блокировки действия в браузере не продолжались. Скриншоты не получены. Ни визуальный прогон, ни реальное перетаскивание в Chrome не выдаются за выполненные.

Автоматические тесты DragController используют синтетические события в тестовом окружении, а не физические касания. Типы SDK и вызовы сверены с официальной документацией и установленным пакетом 2.4.0; тесты адаптера используют mock. Реальные облачные сохранения, загрузка платформенных SDK, host lifecycle и показ рекламы в Playgama/Яндекс/VK требуют sandbox-проверки с действительными ID площадок.

## Перед публикацией

1. Выполнить живой прогон и сохранить скриншоты по матрице.
2. Настроить реальные платформенные идентификаторы в `public/playgama-bridge-config.json`, если они требуются хостом.
3. Пересобрать `npm run package`, загрузить QA ZIP в sandbox, проверить облачное продолжение между запусками и рекламу только после окончания партии.
4. После QA переходить к балансировке, затем к ежедневным испытаниям, прогрессии и rewarded.
