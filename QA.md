## 2.0.3 — IMG_1522, резкое движение и переполнение лотка

Исходный файл IMG_1522.MP4: 384×832, 12.967 с, 389 кадров, постоянные 30 FPS. Просмотрены контактный лист всей записи и покадровая последовательность первого жеста (0–1.1 с). Подтверждённое переполнение: универсальный scale .59 давал пятиблочной фигуре габарит около 153 логических px при высоте слота 110. Верх заходил на YOUR NEXT MOVES/«СЛЕДУЮЩИЕ ХОДЫ»; горизонтальная линия также могла зайти к соседям. `trayLayout` теперь ограничивает ширину и высоту каждой формы с внутренним отступом. Точные transform используются для hit-test, возврата, появления и обеих фигур rewarded-перехода. Параметры контакта/подъёма 22 CSS px не менялись. Появление лотка без Back.Out overshoot; переход замены учитывает разные размеры исходной и новой формы.

Другие воспроизведённые кодом/регрессиями дефекты: любой resize отменял жест и заново записывал transform всей игры даже при неизменной геометрии; pickup-прогресс между кадрами мог оставаться устаревшим при уже полученном pointermove; отпускание мгновенно скрывало переносимую фигуру и показывало live-клетки в их конечных центрах/масштабе. Теперь no-op resize игнорируется, новый pointermove продвигает pickup по реальному времени, release не пересчитывает скрытый прогресс; берётся последняя coalesced-точка и, при наличии поддержки, pointerrawupdate. Нет сглаживания/экстраполяции координат или добавленной задержки ввода. Живые клетки доводятся из показанной позы за 90 мс; модель уже обновлена, следующий ход разрешён. Очистка/повторное использование координаты отменяет посадочный tween, восстанавливая исходный центр/масштаб. Это проверено отдельной регрессией.

Снижение потенциальной нагрузки: Phaser touch/mouse/keyboard/gamepad выключены в конфигурации, так как игра использует собственные обработчики Pointer Events и window keydown. Раньше touch параллельно проходил через TouchManager/InputManager Phaser, хотя interactive Game Objects отсутствуют. Проверено на реальном App config и живом размещении после отключения. Линейная фильтрация спрайтов сохранена; выключен MSAA WebGL-контекста (его default был true). Backing buffer учитывает отображаемый CSS-масштаб, cap DPR 2 сохранён. ## 2.0.2 — непрерывный ввод во время очистки

Подтверждённая причина паузы: `App.settled` и `GameScene.locked` запрещали следующий захват до таймеров 45 + 215 мс (80 мс при Reduced Motion). Доска визуально очищалась через tweens живых клеток, после чего отложенный callback повторно рисовал сохранённый результат хода. Простое снятие блокировки позволило бы старой анимации скрыть новую клетку или вернуть устаревшую доску.

Теперь неизменяемое ядро сразу вычисляет весь результат; `App.onPlace` применяет и сохраняет его синхронно до визуального отклика. `GameScene` один раз обновляет актуальное поле и лоток, затем передаёт самостоятельный `ClearEvent` с копиями координат/цветов, счётом и комбо. `ClearEffects` не получает игровую модель. Призраки, полосы и частицы находятся под слоем живых клеток; завершение их анимации только скрывает декоративные объекты. Следующий захват доступен сразу, включая первый кадр появления новой тройки с alpha=0. Контакт, подъём, preview/drop и смещения пальца не менялись. Истинный Game Over сразу сохраняется и запрещает невозможные ходы; задерживается только показ итогового окна, с проверкой идентичности состояния и отменой при смене партии.

Canvas Text count означает вызов API, а не измеренное число GPU uploads: Phaser может пропустить растеризацию одинаковой строки.

Дорогих runtime blur/glow pipelines/фильтров в этих модулях нет: свечение — спрайты с ADD, shadowBlur используется только при создании текстур. Возможные GPU fill-rate/переключения текстур, загрузка Canvas Text, GC и стоимость Storage на устройстве требуют Web Inspector; синхронный длинный блокирующий вызов на телефоне не подтверждён. Сериализация небольшого профиля остаётся на ходе, Bridge-записи идут через существующую очередь без ожидания анимации.

### Внедрённые оптимизации

Постоянные пулы: 128 призраков блоков, 32 пары beam/glint, 32 частицы, 8 импульсов, 8 слотов старта звука/сообщения и два сообщения по 32 символа плюс заголовок. Всё создаётся при инициализации. При переполнении заменяется старейший декоративный слот; модель не затрагивается. Один цикл обновления без tweens и временных массивов на кадр, пропуск цикла в покое; сброс скрывает объекты и отменяет ожидающие звуковые callbacks. Атлас цифр/Combo и четырёх заголовков создаётся один раз вместо изменения Canvas Text при ходе. Полноэкранные ADD-волны объединяются в одну; вторичные частицы используют адаптивный бюджет NeonEffects. Прежние пулы поля, переноса, preview и декоративного следа сохранены; `nodes()` возвращает постоянный массив. Новые клетки отрисовываются поверх старой очистки. Фаски, объём, блики, волна, комбо и рекорд сохранены; весь визуал ради FPS не отключается.

DEV-панель: `npm run dev`, открыть `/?mock=1&perf=1`, нажать Reset metrics после загрузки. Показывает FPS, средний/максимальный frame time, активные декоративные объекты, tweens и CPU placement/clear preparation. Обновляет DOM раз в 500 мс, исключает скрытые/платформенные паузы; ничего не сохраняет и не отправляет. Модуль и строки панели исключаются из production, что проверяется `verify:build`.
