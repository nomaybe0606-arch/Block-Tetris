# QA — Grid Pulse 2.0, 1 ноября 2026

## Обновление 2.0

Neon Glass: новые программные текстуры блоков и поля, фаски, внутренние тени, мягкие блики, гармоничная неоновая палитра. Активная фигура получила декоративные свечение/тень и короткий след, очистка — затухание со сжатием клеток и цветовые импульсы, несколько линий — усиленную волну. Добавлены переходы, анимация рекорда и отдельная трансформация фигуры за 420 мс. Точное положение фигуры, координаты preview/drop, формулы очков и 8×8 не менялись.

32 частицы, 6 следов и 8 импульсов переиспользуются; падение FPS снижает декоративный бюджет. Reduced Motion и выключение интенсивных эффектов отключают вторичные эффекты. Пулы очищаются при уходе в меню и уничтожаются при shutdown. В лотке место под кнопку замены резервируется только на поддерживаемой платформе после шестого хода; hit-test использует реальный transform.

Замены: три за партию, открытие после шести размещений, явное подтверждение рекламы, детерминированная допустимая форма до просмотра. Поддержка проверяется Bridge, placement `piece_swap`. Награда только по rewarded, защита от параллельных операций и повторных событий. Отмена, отсутствие рекламы и ошибки не расходуют лимит. Общий рекорд сохранён. Checkpoint перед просмотром и после награды; отказ записи награды предлагает повторить сохранение без ещё одного видео. При полном отказе Storage и закрытии страницы несохранённые изменения, как и обычный ход, могут потеряться.

v1-профиль/партия мигрируют в v2 через прежний ключ Bridge Storage. Used quota, доска, лоток, счёт, best, настройки и выбранный слот восстанавливаются; pending-реклама после перезагрузки отменяется без награды, applied-состояние уже содержит фигуру и расход лимита. Прямое браузерное хранение не добавлено.

Автопроверки: **139 тестов в 9 файлах**, включая все 97 исходных. Добавлены 42 проверки лимита и валидности замен, миграции/перезагрузки, duplicate receipts, предварительного сохранения, save retry без новой рекламы, закрытия/ошибки/no-fill/unsupported, двойного нажатия, таймаута загрузки, исключений подписки/отписки, host pause/audio, запрета двойного interstitial и ограниченных пулов NeonEffects. Это тесты с синтетическим вводом и mock SDK.

Чистый `npm ci`, TypeScript, production build и переносимая платформенная сборка проверяются; HTTP-проверка покрывает 28 адресов для `/Block-Puzzle/` и `/`, SDK/config, чанки, SVG и 14 OGG/MP3. `verify:build` дополнительно запрещает DEV rewarded-код в production. Vite обновлён до 7.3.7, Vitest до 4.1.12, esbuild до 0.28.2: `npm audit` сообщает 0 уязвимостей. Локально Node.js 26.3.0/npm 11.16.0, CI использует Node.js 24.

Браузерная проверка: Computer Use снова вернул пустой список браузеров и `The browser access host is unavailable`. Скриншоты и фактический мобильный FPS не получены. Не заявляется успешный визуальный или физический touch-прогон.

Оставшийся ручной QA: iPhone Safari и Android Chrome (малые экраны, DPR, быстрые диагонали, все формы, поворот, отмена жеста); длинная сессия и реальные FPS; Reduced Motion/интенсивные эффекты; keyboard/focus; MP3/audio unlock/возврат из фона. В sandbox Playgama/Яндекс/VK настроить выданные платформой ID, проверить реальные success/cancel/no-fill, порядок событий Bridge, паузу и звук, три замены, F5 после подтверждённого сохранения, отказ Storage и общий рекорд между запусками. На публичном Pages rewarded скрыт и не эмулируется. Локальный DEV mock: `?mock=1&rewarded=success|cancel|no-fill|error|duplicate` (в URL указать один сценарий).

## История предыдущих проверок

## Доработка после тестирования на телефоне

Причины: SDK 2.4.0 создавал собственный logo-loading по умолчанию; в конфигурации не было отключения. Старый drag принимал касание прямоугольного слота, центрировал фигуру, вычитал 88 логических единиц для touch и отдельно сглаживал визуальные координаты. Preview рассчитывался по целевой, а не показанной позиции.

Изменения: официальный `disableLoadingLogo: true` вместе с `loadingScreenType: "none"`; hit-testing по клеткам и фактическому tray transform; контакт в локальной системе фигуры; пропорциональный размерам подъём с 22 CSS px просветом; рост за 100 мс; прямое движение; одна поза preview/drop. Подъём обновляется в Phaser update перед render, без независимого RAF. Отпускание использует последний показанный прогресс анимации; быстрый жест не ждёт её завершения. Отдельно исправлена отмена: события второго пальца не отменяют первый. Возврат — 130 мс, повторный захват возможен сразу.

Эффекты: короткие световые полосы и проход по строкам/столбцам, максимум 14/24 частицы, более компактное единичное сообщение, синхронный старт clear/combo-аудио с эффектом. Reduced Motion — без проходов, частиц и движения текста. Изменений в правилах, формах и балансе `src/core` / `src/config/balance.ts` нет; workflow GitHub Pages сохранён.

Проверки: TypeScript; 97 тестов в 5 файлах; production build и HTTP-проверка 28 URL, включая config и все звуки. Новые тесты проверяют контакты на концах разных фигур, рост вокруг контакта, CSS-масштабы 0.5–1.5 и DPR 1/2/3, быстрый drop до первого кадра, последний pointerup без move, совпадение preview/drop, границы, multi-touch, отмену, resize, Reduced Motion, лимит частиц и отсутствие накопления надписей. Это синтетические тесты, не физические касания.

Браузерная проверка в этом этапе недоступна: inventory Computer Use сообщает `The browser access host is unavailable`, список управляемых браузеров пуст. Мобильные viewport, iPhone Safari и Android Chrome живьём не проверялись; успешного физического QA не заявлено. Следующий ручной прогон: первый холодный запуск без SDK-логотипа; захват каждого края длинных/L/T/3×3 фигур; быстрые диагонали и отпускания; повторный захват во время возврата; все края поля; Reduced Motion и звук.

## GitHub Pages — исправление публикации в Block-Puzzle

Добавлены отдельный Git-репозиторий `main`, исключения зависимостей/сборки/архивов/секретов, `.gitattributes`, Node.js 24 для CI и workflow `.github/workflows/pages.yml`. Production использует `/Block-Puzzle/`, dev — `/`. Игровые модули `src` не менялись при настройке публикации.

TypeScript и 58 тестов прошли, сборка GitHub Pages создана. Проверка сборки проверяет 28 HTTP-адресов под `/Block-Puzzle/`, ожидаемые байты и MIME-типы, включая SDK, конфигурацию и 14 аудиофайлов. Все файлы `public` совпадают с выходными побайтно.

Дополнительно проверены настоящий Vite dev-сервер на `/` (страница, TypeScript-модуль, SDK, JSON и музыка — HTTP 200) и Vite production-preview на `/Block-Puzzle/` (27 файлов — HTTP 200, 14 звуков с audio MIME). Выполнен чистый `npm ci`; существование версий всех пяти официальных Actions проверено по remote tags. Переносимый ZIP для sandbox тоже собран и проверен; в `dist` после проверки оставлена сборка GitHub Pages. Живой браузерный прогон в этом этапе не выполнялся.

Фактический репозиторий — `nomaybe0606-arch/Block-Puzzle`. Первый запуск `41230314209` успешно выполнил всё задание `build`, но упал в `deploy → Configure GitHub Pages`: annotation сообщает `Get Pages site failed` / `HttpError: Not Found`; deployment был пропущен. Это сбой получения настроек Pages. Отдельно обнаружен неверный URL base `/grid-pulse/`, который исправлен на `/Block-Puzzle/` в конфигурации и проверке ресурсов. В deploy явно добавлено `contents: read` наряду с `pages: write` и `id-token: write`.

При авторизованной диагностике Pages API уже вернул HTTP 200 и `build_type: workflow`: текущая настройка источника — GitHub Actions. Предупреждение Node.js 20 у `configure-pages@v5` не является причиной HTTP 404; runner выполняет action на Node.js 24. Доступные данные подтверждают успешную совместимость Node.js 24, установки npm и зависимостей в build исходного запуска. Инструкция и точный адрес сайта обновлены в `GITHUB_PAGES.md`. Реальные реклама и облачные сохранения Bridge требуют отдельного sandbox QA.

## Не подтверждено живым браузером

Автоматизация Chrome через Computer Use была остановлена самим инструментом: он не смог уверенно определить текущий URL Windows-браузера для применения своей политики. После блокировки действия в браузере не продолжались. Скриншоты не получены. Ни визуальный прогон, ни реальное перетаскивание в Chrome не выдаются за выполненные.

Автоматические тесты DragController используют синтетические события в тестовом окружении, а не физические касания. Типы SDK и вызовы сверены с официальной документацией и установленным пакетом 2.4.0; тесты адаптера используют mock. Реальные облачные сохранения, загрузка платформенных SDK, host lifecycle и показ рекламы в Playgama/Яндекс/VK требуют sandbox-проверки с действительными ID площадок.

## Перед публикацией

1. Выполнить живой прогон и сохранить скриншоты по матрице.
2. Настроить реальные платформенные идентификаторы в `public/playgama-bridge-config.json`, если они требуются хостом.
3. Пересобрать `npm run package`, загрузить QA ZIP в sandbox, проверить облачное продолжение между запусками и рекламу только после окончания партии.
4. После QA переходить к балансировке, затем к ежедневным испытаниям, прогрессии и rewarded.
