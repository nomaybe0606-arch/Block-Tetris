# Grid Pulse 2.0.8

CrazyGames Basic Launch подготовлен в отдельной ветке `release/crazygames-grid-pulse`: команды `build:crazygames`, `verify:crazygames`, `package:crazygames`; результат `dist-crazygames/` и `artifacts/grid-pulse-crazygames.zip`. У этой сборки собственный SDK v3, Data и lifecycle; реклама отключена. Инструкция, проверенные артефакты и ограничения: [CRAZYGAMES_RELEASE.md](CRAZYGAMES_RELEASE.md). Имя репозитория, Pages URL и ключи прогресса сохранены; основной workflow не менялся.

Полноценный локальный проект классической головоломки 8×8: TypeScript, Phaser 3, Vite. Собственные блоки с фасками, SVG-иконки и семь оригинальных OGG-ассетов. React и сервер не нужны.

Публикация настроена исключительно для **GitHub Pages**: репозиторий [`nomaybe0606-arch/Block-Tetris`](https://github.com/nomaybe0606-arch/Block-Tetris), адрес `https://nomaybe0606-arch.github.io/Block-Tetris/`. Каждый push в `main` запускает проверки и публикацию через GitHub Actions. Настройка и диагностика: [GITHUB_PAGES.md](GITHUB_PAGES.md).

## Запуск

Требуется Node.js 22.12+ либо актуальная совместимая LTS-версия. Проверено на Node.js 26.3.0.

```sh
npm ci
npm run dev
```

Открыть адрес, напечатанный Vite, обычно `http://127.0.0.1:5173/`. В Windows PowerShell с запрещённым запуском `npm.ps1` использовать `npm.cmd` вместо `npm`.

```sh
npm test                 # Vitest: игровое ядро, ввод, граница Bridge
npm run typecheck        # строгая проверка TypeScript
npm run build            # GitHub Pages → dist/, base /Block-Tetris/
npm run verify:build     # проверка ассетов и HTTP-загрузки под /Block-Tetris/
npm run preview          # http://127.0.0.1:4173/Block-Tetris/
npm run package          # переносимый ZIP только для sandbox QA платформы
npm run build:vk         # VK-версия → dist-vk/ (без Playgama)
npm run verify:vk        # проверка dist-vk/ (scripts/verify-host-build.mjs)
npm run deploy:vk        # сборка, проверка и загрузка на хостинг VK
npm run promo:vk         # картинки для каталога VK → promo/vk/
npm run build:pikabu     # версия для Пикабу Игр → dist-pikabu/
npm run verify:pikabu    # проверка dist-pikabu/
```

Dev-сервер по-прежнему работает от `/`, production и preview — от `/Block-Tetris/`. GitHub Actions собирает и загружает `dist` сам; эту папку не нужно коммитить. Открывать игру через HTTP, а не `file://`.

`npm run package` отдельно создаёт сборку с относительными путями и `artifacts/grid-tetris-2.0.8-platform.zip` для последующего QA в sandbox Playgama/Яндекс/VK. Это не альтернативный способ хостинга. `index.html` находится в корне ZIP. После такой команды для GitHub Pages снова выполнить `npm run build`.

## Что работает

- Поле 8×8, три расходуемые в любом порядке фигуры, 38 заранее заданных форм/ориентаций. Ручного вращения нет.
- Мышь и touch, сохранение точки захвата на конкретной клетке, подъём с учётом размера фигуры и CSS-масштаба, точный preview, подсветка пересечений/границ и готовых линий. Отмена pointercancel/lost capture/blur/resize/скрытия вкладки. Следующую фигуру можно захватить сразу после хода, пока продолжается очистка.
- Одновременная очистка строк и столбцов без гравитации; очки, серии, рекорд, количество линий и максимум комбо.
- Взвешенная генерация, учёт заполненности и повторов, гарантия хотя бы одного хода в новой тройке, если есть подходящая фигура. Три необязательные rewarded-замены после шестой установленной фигуры на поддерживаемых площадках.
- Главное меню, продолжение, интерактивное обучение с первым размещением и очисткой строки, настройки, подтверждение новой партии, Game Over.
- RU/EN, музыка/эффекты/общий mute, Reduced Motion с учётом системной настройки, отдельный переключатель интенсивных эффектов; MP3-fallback для браузеров без Vorbis.
- Neon Glass: градиенты и фаски блоков, внутренние тени поля, блики, свечение и тень активной фигуры, короткий след, световые волны очистки, анимация счёта и рекорда, надписи Good/Great/Excellent/Amazing и Combo.
- Логическая сцена 480×850, равномерное масштабирование, safe areas, Canvas/WebGL, буфер до двух пикселей на отображаемый CSS-пиксель. Нет прокрутки и внешних игровых ассетов.

Клавиатура: `1`–`3` — фигура, стрелки — позиция, `Enter` — поставить, `Esc` — отменить. Кнопки и диалоги доступны через Tab; диалоги удерживают фокус. Доска не имеет полноценного невизуального озвучивания каждой клетки.

## Управление и эффекты

`src/config/controls.ts` содержит параметры управления:

| Параметр | Значение | Назначение |
| --- | --- | --- |
| `pickupDurationMs` | 100 мс | Рост от фактического масштаба в лотке до полного и плавный подъём |
| `targetScale` | 1 | Размер фигуры при переносе |
| `touchClearanceCss` | 22 CSS px | Минимальный просвет от пальца до нижнего края поднятой фигуры |
| `touchHitSlopCss` | 8 CSS px | Допуск касания возле видимых клеток |
| `mouseHitSlopCss` | 3 CSS px | Допуск мыши; вертикального подъёма для мыши нет |
| `returnDurationMs` | 130 мс | Возврат ошибочного drop; новый захват завершает возврат немедленно |

При прямом захвате блока учитывается реальная позиция/масштаб фигуры, в том числе во время появления. Контакт переводится в локальные координаты фигуры; увеличение происходит вокруг него. Lift учитывает высоту фигуры, положение контакта и масштаб экрана. Фиксированное смещение на 88 игровых единиц удалено.

В 2.0.6 вся область ниже внешнего края поля разделена на три невидимые вертикальные колонки. Нажатие на пустое место своей колонки (в том числе под фигурой) тоже начинает перенос. Точное попадание в блок сохраняет контакт; пустое место выбирает центральный grip. Начальная позиция совпадает с показанной фигурой, смещение плавно исчезает за прежние 100 мс pickup; перемещение пальца применяется сразу, release использует ту же позу, что preview. Израсходованный слот не перенаправляет касание соседу. Зона заканчивается у нижнего края игрового canvas; при показанной кнопке замены её нижняя область зарезервирована отдельно. Подложек/рамок лотка нет. Поле поднято на 28 логических px (GRID.y=202), верхний HUD компактнее, фигуры расположены выше. Размер поля, баланс и скорость переноса сохранены.

Простое касание пустого места без перетаскивания возвращает фигуру обратно: её подъём сам по себе не размещает блоки. Для подтверждения такого удалённого захвата достаточно движения пальца на 3 CSS px; сам захват, preview и движение отображаются сразу, порог проверяется только при отпускании. Прямой захват блока работает как прежде.

В 2.0.8 комбо ×2…×8 получило отдельную анимацию: чем выше множитель, тем крупнее надпись, ярче ореол/кольцо и больше искр (2…6 с учётом адаптивного бюджета). Надписи увеличены ещё примерно на 12%, ореол/кольцо/искры — примерно на 10%. Длительность растёт с множителем: ×2 — 520 мс, затем +30 мс на уровень, до ×8 — 700 мс. Быстрое появление остаётся 150 мс; следующий ход не ждёт окончания. 14 RU/EN надписей растеризуются в текстуру при запуске. Один пул из девяти изображений, без новых tweens/фильтров/Canvas Text на событии; новое комбо заменяет предыдущее. Множители выше восьми отображаются как ×8 в соответствии с существующим лимитом бонуса. Reduced Motion/выключенные интенсивные эффекты — неподвижная надпись с коротким затуханием. Локальный визуальный тест: `/?mock=1&qa=combo&combo=8` → Continue → клавиша 1, семь ArrowRight, Enter. Параметр combo от 2 до 8 задаёт тестовый уровень; DEV fixture не включён в production.

Движение пальца применяется сразу, без инерционного сглаживания. Только короткая анимация подъёма обновляется до отрисовки кадра Phaser. Preview и release получают одну и ту же позу; при отпускании не выполняется скрытое продвижение анимации. Быстрый жест не требует ожидания 100 мс. Перевод из клиентских координат использует CSS-прямоугольник canvas и логическую сцену 480×850, а не размер буфера DPR.

`src/config/feedback.ts` содержит отдельные параметры эффектов: начало очистки через 45 мс, затухание 215 мс, световой проход 170 мс, максимум 14 частиц для одной линии и 24 для нескольких. Звук clear/combo запускается в тот же callback, что вспышка. Сообщения не наслаиваются; Reduced Motion убирает проход, частицы и перемещение текста.

В 2.0 фигура по-прежнему следует за жестом напрямую. Только декоративные тень и свечение догоняют её с постоянной 42 мс; допустимая позиция preview/drop от них не зависит. Пулы ограничены 32 частицами, 6 следами и 8 импульсами; текстуры создаются один раз. После устойчивого падения ниже 44 FPS бюджет частиц уменьшается вдвое и след отключается, при восстановлении FPS качество возвращается. `src/config/animation.ts` задаёт тайминги: окна 180 мс, замена 420 мс, рекорд 700 мс. Интенсивные эффекты можно выключить без изменения точности управления.

В 2.0.1 после разбора записи с телефона устранены лишние пересоздания: 64 клетки поля, 16 отражений и 9 клеток переносимой фигуры создаются заранее; неизменившиеся фигуры лотка сохраняются. Подсказка использует два постоянных Graphics. Обычная установка обновляет поле один раз; неподвижное обрамление запекается в текстуру. Вспышка, 16 пар световых полос/бликов и два текстовых сообщения также переиспользуются. При половинном бюджете частицы, запрашиваемые по одной, распределяются через дробный остаток и не исчезают полностью.

Установка получила сжатие и упругий возврат за 120 мс, лоток — появление за 220 мс со сдвигом 35 мс между фигурами, очистка — более заметную волну со сжатием клеток и световой проход. Счёт плавно меняется за 240 мс и не перезапускается от событий сохранения/паузы. DOM поля интерфейса и окон сохраняется; обновляются отдельные значения и состояния, фокус и анимация переключателей остаются на месте. После последней установки перед Game Over добавлено 180 мс для завершения отклика; обычные ходы дополнительного ожидания не получили. Reduced Motion убирает дополнительное ожидание и движение.

В 2.0.2 очистка работает независимо от ввода: ядро сразу возвращает очищенную доску, очки, комбо, лоток и Game Over; приложение сохраняет результат до запуска эффектов. `ClearEvent` копирует координаты и цвета удалённых клеток. Отдельный слой призраков расположен под актуальными клетками; анимация не изменяет игровую модель и не перерисовывает устаревшую доску по окончании. Game Over может задержать только показ окна, но его логический результат уже сохранён.

Очистка использует фиксированные пулы: 128 призраков клеток, 32 пары полос/бликов, 32 частицы, 8 световых импульсов и два сообщения из атласа символов. Текст растеризуется при запуске. Эффекты обновляются одним циклом без собственных tweens; полноэкранные волны объединяются. Свечение фигуры, след и рекорд сохраняются. Сравнение с 2.0.1 и ограничения измерений — в `QA.md`.

DEV-диагностика включается только в локальной разработке: `http://127.0.0.1:5173/?mock=1&perf=1`. Она показывает FPS, среднее и максимальное время кадра, число активных декоративных объектов/tweens, CPU-время размещения и подготовки очистки. Нажать **Reset metrics** после загрузки, тестировать активную вкладку. Скрытые/платформенные паузы исключаются. Production и платформенный ZIP не содержат эту панель; `verify:build` это проверяет. Для теста с телефона dev-сервер нужно отдельно открыть в своей локальной сети; публичный Pages не включает DEV mock.

Happy DOM используется только в devDependencies для тестов постоянства DOM, счёта, диалогов и фокуса. Синтетические тесты подтверждают ограниченное число объектов, но не измеряют FPS на физическом iPhone. Матрица повторной проверки и результаты — в `QA.md`.

В 2.0.3 размер каждой фигуры лотка ограничен её собственным слотом 128×110: длинные фигуры не заходят на подпись и соседей. Захват и возврат читают индивидуальный transform; смена размера не меняет контакт/подъём фигуры при переносе. Отпускание доводит живые клетки из последней показанной позы в выбранные клетки за 90 мс без ожидания следующего ввода. Повторное использование координаты отменяет старую посадку и восстанавливает точное положение клетки.

Дублирующие touch/mouse/keyboard менеджеры Phaser отключены: игра использует собственные DOM Pointer Events и клавиатуру. Последняя coalesced-точка применяется сразу; `pointerrawupdate` используется при поддержке браузера. Пропущенный кадр не оставляет pickup-прогресс устаревшим на следующем pointermove; release сохраняет последнюю позу preview. Resize с прежними размерами не отменяет жест и не переписывает transform всей игры. Реальное изменение размеров по-прежнему отменяет текущий жест.

Буфер вычисляется по исходному отображаемому масштабу и DPR (cap 2), сохраняется при resize; отключён дополнительный framebuffer MSAA, а линейная фильтрация текстур сохранена. На ширине 390 CSS px и DPR 3 это 780×1381 вместо 960×1700, около −34% пикселей. Это снижение нагрузки, а не обещание FPS физического устройства. Воспроизводимый локальный сценарий длинных фигур: `/?mock=1&qa=tray` → Continue game; DEV fixture не включается в Pages или платформенный ZIP.

Отражения поля собраны в отдельный ADD-слой под блоками. На заполненном поле это сокращает переключения ADD/NORMAL в рендере отражений/клеток с 32 до 2 за кадр, сохраняя все отражения. В Phaser смена режима вызывает flush; число реальных GPU draw calls и frame time на iPhone ещё требуют профилирования.

В 2.0.5 блоки, поле, свечение, полосы, частицы и подсказка используют общий атлас 1024×1024. Подсказка — постоянные спрайты, предсказание линий — переиспользуемый буфер, без Graphics tessellation/копии доски при движении. Короткие звуки один раз декодируются в шесть Web Audio buffers; до 12 голосов, без HTML media seek на каждом захвате/очистке. Музыка остаётся потоковой; для браузеров без Web Audio или ошибок декодирования доступен ленивый fallback. До окончания загрузки буфера звуковой cue пропускается, чтобы не запускать декодер во время жеста; игровой ввод не ждёт аудио. Счётчик не переписывает одинаковый DOM-текст каждый кадр. Canvas отделён paint/compositing-границей от DOM.

Анимации используют реальный delta без десятикадрового усреднения Phaser и искусственного обрезания шага эффекта до 100 мс. Тайминги эффектов, подъёма, возврата и доводки не увеличены; координаты пальца не интерполируются. Для повторяемого DEV-теста: `/performance.html` → Run 12-second benchmark. Отдельный стенд воспроизводит заполненное поле, движущийся preview и 21 очистку четырёх линий за 12 с, сообщает p50/p95/p99/max frame time и CPU update. Он не включает App/Storage/аудио и не измеряет iPhone. В production этот entry отсутствует; настоящую игру со звуком проверять отдельно через `/?mock=1&qa=tray&perf=1`. Панель показывает также число декодированных буферов и активных голосов.

## Три замены

Параметры находятся в `src/config/monetization.ts`: максимум 3, начальный лимит 3, один rewarded-просмотр на замену, разблокировка после 6 размещений. Кнопка появляется только в обычной продолжающейся партии и при поддержке рекламы. На GitHub Pages она скрыта: публичная версия не имитирует рекламу.

Игрок выбирает оставшуюся фигуру, заранее видит замену и пример допустимой позиции, затем отдельно подтверждает просмотр. Предложение детерминировано состоянием поля и выбранным слотом: закрытие окна не даёт перебора. Исходная форма исключается, формы из 2–4 клеток получают больший вес, одиночная клетка возможна только при отсутствии более крупных допустимых альтернатив. Нет альтернатив — нет рекламного запроса. Поле, очки и игровой RNG при замене не меняются; общий рекорд остаётся единым.

Перед рекламой сохраняется операция, ввод заморожен. Только `rewarded` атомарно меняет фигуру и расходует одну замену; `closed`, отмена, no-fill, ошибка и повторные callbacks дополнительных замен не дают. Записи проходят через долговечный checkpoint существующей очереди Bridge Storage. При ошибке сохранения подтверждённой награды окно предлагает повторить сохранение без повторного просмотра, удерживая ввод заблокированным. Не закрывайте страницу до успешного сохранения: при недоступном Storage гарантировать запись на диск невозможно.

Схема профиля и партии — v2, ключ Storage остаётся `grid-pulse-v1`. Старые v1-сохранения мигрируют с доской, счётом, рекордом и настройками; лимит инициализируется без сброса партии. Использованный лимит и выбранный слот сохраняются. После перезагрузки незавершённая реклама отменяется без награды; уже применённая сохранённая замена восстанавливается вместе с расходом лимита.

## Правила баланса

`src/config/balance.ts` содержит все параметры:

- клетка: +1;
- линии за один ход: `10 × количество² × min(комбо, 8)`;
- первое очищение: комбо 1; следующее увеличивает серию;
- два промежуточных хода без очистки разрешены; третий сбрасывает серию;
- число линий — сумма строк и столбцов, пересечённая клетка исчезает один раз;
- рекорд и статистика сохраняются после каждого хода.

Оригинальная механика используется как жанровый ориентир. Формулы и ассеты не выдаются за точную копию Block Blast.

## Playgama Bridge

GitHub Pages используется для тестирования геймплея и интерфейса. Наличие SDK на странице не подтверждает работоспособность реальной рекламы или облачных сохранений: их необходимо отдельно проверять в sandbox платформы. Новых способов хранения ради GitHub Pages не добавлено.

Официальный npm SDK `@playgama/bridge@2.4.0` и официальный Vite-плагин с `mode: 'local'`. SDK находится в сборке отдельным заменяемым `playgama-bridge.js`, CDN для игрового кода и ассетов не нужен.

В `public/playgama-bridge-config.json` заданы официальные `disableLoadingLogo: true` и `loadingScreenType: "none"`. У версии 2.4.0 оба параметра поддерживаются; без них SDK по умолчанию создаёт загрузочный логотип. Конфигурация читается до создания его визуальных элементов, поэтому DOM SDK не скрывается и не изменяется. Остаётся собственная загрузка Grid Pulse; порядок инициализации, Storage и lifecycle сохранены. Основание: [исходник SDK 2.4.0, setupLoadingVisuals](https://github.com/Playgama/bridge/blob/v2.4.0/src/PlaygamaBridge.ts#L311-L334). Если хост требует своё загрузочное представление, адаптировать platform override по его официальным правилам и проверить в sandbox; чужой host SDK не модифицируется.

Порядок: `bridge.initialize()` → `bridge.storage.get()` → проверка профиля → запуск Phaser → первое интерактивное меню → `game_ready`.

Сохранения целиком идут через `bridge.storage.get/set`, ключ `grid-pulse-v1`. Сохраняются доска, частично израсходованный лоток, счёт, RNG, комбо, статистика, настройки и завершённость обучения. Проверяются версия, размеры, фигуры и числовые значения. Записи сериализуются; ожидающие промежуточные состояния заменяются последним, чтобы старая запись не затёрла новый ход. Ошибка хранения не завершает игру, при последующих изменениях запись повторяется. При ошибке инициализации игра продолжает работу в памяти с предупреждением о сохранении. Недоступные данные не считаются успешно восстановленными.

Язык и разрешение аудио читаются из `platform.language` / `platform.isAudioEnabled`. Обработаны универсальные события `AUDIO_STATE_CHANGED` и `PAUSE_STATE_CHANGED`, текущая пауза, уже открытая реклама, видимость вкладки. При паузе жест отменяется, анимации и аудио приостанавливаются. Состояние сохраняется на ходах, настройках и уходе со страницы; запись на `pagehide` — дополнительная попытка, не единственная точка сохранения.

`PlatformService.gameOver(gameId)` вызывает `level_failed` и `showInterstitial('game_over')` после окончания партии, если формат поддерживается. Повтор для той же партии подавляется; во время другой рекламы и непосредственно после rewarded interstitial не вызывается. Интервал SDK — 60 секунд, ограничения конкретной площадки не обходятся. Покупки и лидерборды не реализованы.

`RewardedAdService` использует `bridge.advertisement.isRewardedSupported`, `showRewarded('piece_swap')` и событие `REWARDED_STATE_CHANGED`: loading/opened/rewarded/closed/failed. Placement `piece_swap` объявлен в конфигурации. Одновременно разрешена одна операция; загрузка без открытия завершается через 15 секунд, таймер не прерывает открытое видео. Игровая пауза объединяет состояние host, рекламу и скрытую вкладку; звук восстанавливается только при разрешении host и пользовательских настроек.

`public/playgama-bridge-config.json` копируется рядом с `index.html`. Общая конфигурация валидна и не содержит вымышленных ID. Для публикации необходимо внести выданные площадкой идентификаторы, если они требуются, через официальный конфигуратор, затем выполнить QA в sandbox Playgama / Яндекс / VK. Платформенные SDK и реклама могут обращаться к сети; требование о локальных ресурсах относится к самой игре.

Для изолированной разработки: `http://127.0.0.1:5173/?mock=1`. Это явный mock **только dev-режима**, хранит данные в памяти до перезагрузки; ветка удаляется при production-сборке. По умолчанию и в production используется настоящий SDK, в том числе его собственный fallback для неподдерживаемой площадки. Прямых обращений игры к localStorage, IndexedDB или cookies нет.

Локальные сценарии рекламы: `?mock=1&rewarded=success`, `cancel`, `no-fill`, `error`, `duplicate`. После шести установленных фигур откройте окно замены. Mock допускается только при DEV и hostname localhost/127.0.0.1/[::1]. Production-проверка отклоняет сборку с его кодом или отдельным чанком. Эти сценарии проверяют интерфейс, а не коммерческие показы и облачное хранение.

## VK

VK-версия собирается отдельным режимом `vk` (`npm run build:vk` → `dist-vk/`, относительные пути). Вместо Playgama Bridge используется нативный `@vkontakte/vk-bridge` — адаптер `src/platform/VkPlatform.ts`. Каждая сборка содержит только свой SDK: `main.ts` загружает платформу динамически, а `verify:vk` проверяет, что в `dist-vk/` нет Playgama и dev-моков. Лицензия и notices для VK Bridge подставляются в сборку автоматически.

- `VKWebAppInit` вызывается сразу после маленького стартового чанка, до загрузки Phaser. Вне VK игра запускается без сохранения (как при ошибке Bridge).
- Язык — из параметра запуска `vk_language`.
- Сохранение — VK Storage, ключ `grid-pulse-v1`, кусками по 4000 байт в двух слотах: указатель переключается только после записи всех кусков, поэтому прерванная запись не портит прошлое сохранение. Ходы пишутся пачкой раз в 10 секунд (у VK Storage лимит запросов), сразу — при сворачивании (`VKWebAppViewHide`), уходе со страницы, конце партии и после награды за рекламу. Если прочитать сохранение не удалось, запись отключается, чтобы не затереть облачный прогресс.
- Rewarded (замена фигуры) — `VKWebAppCheckNativeAds`/`VKWebAppShowNativeAds` с `reward`; награда только при `result: true`. Interstitial — после проигрыша, не чаще раза в минуту и не сразу после rewarded. Баннер `VKWebAppShowBannerAd` (снизу, `resize`) — только в главном меню; закрытый игроком баннер больше не показывается в этой сессии.
- В настройках VK-версии есть ссылка «Написать в поддержку» (`VK.supportUrl`).

Перед первой выкладкой: создать приложение VK, вписать его ID в `vk-hosting-config.json` (`app_id`, сейчас 0 — `deploy:vk` остановится с ошибкой), выполнить `npm run deploy:vk` и проверить рекламу и сохранения в самом VK. Картинки для каталога лежат в `promo/vk/` (иконки 576/278/150/32, сниппет 1120×630, скриншоты 1200×600).

Локально: `npm run dev:vk` (с `?mock=1` — память вместо VK) или `npx vite preview --mode vk` для собранной версии.

## Пикабу Игры

Режим `pikabu` (`npm run build:pikabu` → `dist-pikabu/`, относительные пути), адаптер `src/platform/PikabuPlatform.ts`. SDK площадка не даёт в npm: адаптер подключает официальный скрипт `https://games.pikabu.ru/sdk/sdk.js` и вызывает `PkbSDK.init()`. SDK работает только на games.pikabu.ru и в тестовом окружении Студии; в других местах игра через 8 секунд запускается без сохранения.

- Интерфейс по умолчанию русский (требование площадки), экран загрузки тоже.
- `sdk.gameStarted()` — один раз, когда экран загрузки исчез и меню готово.
- Сохранение — `sdk.storage`, ключ `grid-pulse-v1`. `set()` SDK сам отправляет на сервер; явный `flush()` (лимит 100 за 5 минут) — только на контрольных точках, при скрытии страницы и в конце партии. После временной ошибки — одна повторная попытка через 15 с. После `REVISION_CONFLICT` (игра открыта в другой вкладке) запись прекращается до перезагрузки. Если загрузка сохранения не удалась, запись отключается.
- Rewarded (замена фигуры) — `canShow()` перед каждым показом, награда только при `reward: true`. Fullscreen — после проигрыша, не чаще раза в 120 с, не в первые 2 минуты и не сразу после rewarded. Preloader-реклама не используется.

Площадка не хранит сборки, поэтому версия для Пикабу публикуется вместе с GitHub Pages: workflow собирает `dist-pikabu/`, проверяет её и кладёт в `dist/pikabu/`. Ссылка для Студии: https://nomaybe0606-arch.github.io/Block-Tetris/pikabu/ . Каждый push в `main` сразу обновляет игру на Пикабу — без повторной модерации, поэтому в `main` должна попадать только проверенная версия. Перед модерацией: тестовое окружение в Студии (раздел «Тестирование»), реквизиты команды (Настройки — Документы). Документация: https://games.pikabu.ru/sdk/docs

## Структура

```text
src/core/          чистое ядро, фигуры, генератор, RNG, сериализация
src/scenes/        сцена Phaser и игровой feedback-цикл
src/rendering/     текстуры, доска, эффекты
src/input/         жизненный цикл pointer и перевод координат
src/ui/            DOM-интерфейс и собственные SVG-иконки
src/audio/         воспроизведение локальных OGG
src/platform/      Bridge, сохранение, реклама, профиль
src/localization/  русские и английские строки
src/config/        баланс и геометрия
public/assets/     аудио и происхождение ресурсов
tests/             Vitest
scripts/           генерация аудио, проверка и упаковка
```

`scripts/generate-audio.mjs` воспроизводимо генерирует оригинальную музыку/эффекты **до сборки** и кодирует их через FFmpeg. Готовые OGG уже включены в проект; FFmpeg для игры и сборки не нужен. Команда регенерации: `npm run audio:generate`. Происхождение и разрешения описаны в `public/assets/LICENSES.md`, библиотеки — в `public/THIRD_PARTY_NOTICES.md`.

## Проверки и следующий этап

См. `QA.md`. Автотесты и сборка не заменяют живую проверку touch на iOS/Android, визуальный просмотр на разных размерах и проверку настоящей рекламы/облачных сохранений в sandbox площадок. Заявлять подтверждённые 60 FPS на реальных телефонах до такого прогона нельзя.

Следующий этап: пройти матрицу QA, настроить идентификаторы площадок, проверить реальную рекламу и облачное продолжение; затем балансировать по игровым сессиям. Ежедневные испытания и прогрессия остаются отдельным этапом.
